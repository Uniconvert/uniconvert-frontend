# Uniconvert 반응형 비율 & 상호작용 최적화 가이드

> 상태: Draft  
> 최종 수정: 2026-07-16  
> 대상: Uniconvert Web Frontend  
> 목적: 화면을 단순 축소하지 않고, 기기별 정보 우선순위와 조작 방식을 최적화한다.

---

## 1. 핵심 원칙

1. 데스크톱 화면을 모바일에 그대로 축소하지 않는다.
2. 고정 좌표보다 Grid, Flex, `minmax`, `clamp`를 사용한다.
3. 화면이 작아질수록 핵심 정보와 주요 행동을 먼저 보여준다.
4. Hover 없이도 모든 기능을 사용할 수 있어야 한다.
5. 마우스, 터치, 키보드에서 동일한 결과를 얻을 수 있어야 한다.
6. Loading, Error, Empty, Success 상태에서 레이아웃이 무너지지 않아야 한다.

---

## 2. 지원 화면 범위

| 구분 | 너비 기준 | 주요 검증 크기 | 레이아웃 목표 |
|---|---:|---|---|
| Wide Desktop | 1441px 이상 | 1920×1080 | 사이드바 + 2열 콘텐츠 |
| Desktop | 1025~1440px | 1440×900, 1280×720 | 사이드바 유지 또는 콘텐츠 1열 전환 |
| Tablet | 641~1024px | 1024×768, 768×1024 | 상단 내비게이션 + 1열 |
| Mobile | 640px 이하 | 390×844, 360×800 | 핵심 기능 중심 단일 열 |

### 프로젝트 Breakpoint 역할

| Breakpoint | 역할 |
|---|---|
| `90rem` | 넓은 대시보드 카드 비율 조정 |
| `87.5rem` | 메인·미리보기 2열을 1열로 전환 |
| `75rem` | 데스크톱 레이아웃 간격 축소 |
| `64rem` | Sidebar를 상단 내비게이션으로 전환 |
| `48rem` | 카드·폼 2열을 단일 열로 전환 |
| `40rem` | 모바일 타이포그래피·간격·버튼 조정 |

Breakpoint는 기기 이름보다 실제 콘텐츠가 깨지는 지점을 기준으로 조정한다.

## 3. 레이아웃 비율 기준

### 3.1 Wide Desktop

```text
Sidebar       고정 약 318px
Workspace     나머지 영역
Main content  약 58~62%
Preview       약 32~36%
Column gap    나머지 여백
```

```css
.page {
  display: grid;
  grid-template-columns:
    minmax(40rem, 54rem)
    minmax(28rem, 34.5rem);
  justify-content: space-between;
  gap: 3rem;
}
```

### 3.2 Desktop

- 콘텐츠 폭이 부족하면 Preview를 오른쪽에 억지로 유지하지 않는다.
- Main과 Preview를 단일 열로 전환한다.
- 카드의 최대 폭은 유지하고 빈 공간은 자연스럽게 배치한다.

### 3.3 Tablet

- Sidebar는 콘텐츠 너비를 과도하게 차지하므로 상단 내비게이션으로 전환한다.
- 주요 카드는 한 열로 쌓는다.
- Preview는 Main 아래로 이동한다.
- 모달은 화면 여백을 유지하면서 `width: min()`을 사용한다.

### 3.4 Mobile

- 주요 버튼은 가능한 경우 전체 너비로 제공한다.
- 장식 이미지는 축소하거나 숨긴다.
- 표는 카드 목록 또는 가로 스크롤 구조로 전환한다.
- 입력 필드와 Label을 세로로 배치한다.
- 화면 하단의 주요 행동은 키보드가 열려도 접근 가능해야 한다.

### 권장 CSS

```css
width: min(100%, 34.5rem);
font-size: clamp(1.5rem, 3vw, 3rem);
grid-template-columns: minmax(0, 1.6fr) minmax(20rem, 1fr);
```

### 피해야 할 CSS

```css
width: 900px;
margin-left: 420px;
position: absolute;
left: 700px;
```

절대 위치는 장식이나 배지처럼 흐름에 영향을 주지 않는 요소에 제한한다.

## 4. 화면별 콘텐츠 우선순위

| 화면 | 1순위 | 2순위 | 작은 화면에서 축소·이동 |
|---|---|---|---|
| 랜딩 | 서비스 가치, 시작하기 | 로그인·회원가입 | 장식 이미지 축소 |
| 지출 입력 | 통화, 금액, 날짜, 저장 | 미리보기 | Preview를 폼 아래로 이동 |
| 지출 내역 | 잔여 예산, 최근 지출 | 카테고리 차트 | 차트를 단순 목록과 병행 |
| Pots | 예산 배분, Pot 목록 | 자동 적립 정보 | 캐릭터·보조 이미지를 축소 |
| 리포트 | 총 지출, 월별 추이 | 이메일 미리보기 | 미리보기를 아래로 이동 |
| 설정 | 리포트 토글, 프로필 | 버전, 장식 | 장식 영역 숨김 가능 |
| 온보딩 | 현재 단계 입력 | 설명·장식 | 카드 전체 너비 사용 |

## 5. 내비게이션 최적화

### Desktop

- Sidebar를 항상 표시한다.
- 현재 메뉴는 배경과 텍스트 색으로 명확하게 표시한다.
- Home 하위 화면은 상단 탭으로 구분한다.

### Tablet·Mobile

- Sidebar를 그대로 축소하지 않는다.
- 상단 가로 메뉴 또는 디자인 확정 후 하단 내비게이션을 사용한다.
- 메뉴가 화면을 넘으면 잘리지 않고 스크롤되거나 우선순위를 조정한다.
- 현재 위치는 `aria-current="page"`와 시각적 스타일을 함께 사용한다.

### 확인 항목

- [ ] 현재 메뉴가 항상 식별된다.
- [ ] 메뉴 선택 영역이 최소 44×44px이다.
- [ ] 키보드 Tab 이동 순서가 화면 순서와 같다.
- [ ] 긴 사용자 이름에서도 Header가 깨지지 않는다.
- [ ] 모바일에서 가로 스크롤이 본문 전체에 생기지 않는다.

## 6. 버튼과 터치 상호작용

버튼은 다음 상태를 가져야 한다.

```text
Default → Hover → Pressed
        → Focus-visible
        → Disabled
        → Loading
        → Success / Error feedback
```

### 기준

- 터치 영역은 최소 44×44px을 권장한다.
- 아이콘만 있는 버튼은 접근 가능한 이름을 제공한다.
- Hover 색상만으로 상태를 표현하지 않는다.
- 저장 중에는 중복 제출을 막는다.
- Disabled 상태에서는 이유를 주변 안내문으로 설명한다.

```tsx
<Button
  type="submit"
  disabled={!isValid || isSaving}
  isLoading={isSaving}
>
  저장
</Button>
```

```tsx
<button type="button" aria-label="프로필 사진 변경">
  <ChangeIcon aria-hidden="true" />
</button>
```

## 7. 폼 상호작용

### 필수 상태

| 상태 | UI 처리 |
|---|---|
| 입력 전 | Label과 예시 Placeholder 제공 |
| 입력 중 | 값 형식과 글자 수 표시 |
| 유효 | 다음 단계 또는 저장 활성화 |
| 유효하지 않음 | 필드 가까이에 구체적인 오류 표시 |
| 전송 중 | 버튼 Loading, 중복 제출 차단 |
| 실패 | 서버 메시지 또는 사용자 행동 안내 |
| 성공 | 저장 완료 피드백과 다음 이동 제공 |

### 모바일 입력 고려

- 금액은 `inputMode="decimal"` 또는 `numeric`을 사용한다.
- 이메일은 `type="email"`을 사용한다.
- 날짜는 기기 기본 날짜 선택을 사용할 수 있다.
- 키보드가 열린 상태에서 주요 버튼이 완전히 가려지지 않는지 확인한다.
- 오류가 발생하면 첫 번째 오류 필드로 포커스를 이동한다.

오류는 색상만 사용하지 않는다.

```tsx
<p role="alert">지출 금액을 입력해주세요.</p>
```

## 8. Loading·Error·Empty·Success

모든 서버 데이터 화면은 네 상태를 설계한다.

| 상태 | 권장 UI |
|---|---|
| Loading | 기존 레이아웃을 유지하는 Skeleton 또는 PageLoading |
| Error | 오류 설명, 재시도 버튼, 이동 경로 |
| Empty | 빈 이유와 첫 행동 CTA |
| Success | 데이터 UI와 완료 피드백 |

```tsx
if (isLoading) return <ExpenseListSkeleton />

if (error) {
  return <ErrorState onRetry={refetch} />
}

if (expenses.length === 0) {
  return (
    <EmptyState
      title="등록된 지출이 없습니다"
      actionLabel="지출 입력하기"
    />
  )
}
```

목록에 데이터를 추가할 때 기존 목록 전체를 빈 로딩 화면으로 바꾸지 않는다.

## 9. 모달·파일 업로드 상호작용

### 모달

- 열릴 때 첫 번째 조작 요소로 포커스를 이동한다.
- Tab 포커스가 모달 밖으로 나가지 않게 한다.
- ESC로 닫을 수 있게 한다.
- 닫힌 뒤 모달을 연 버튼으로 포커스를 돌려준다.
- 배경 스크롤을 막는다.
- 중요한 작업 취소 여부가 명확해야 한다.

### 파일 업로드

- 드래그 앤 드롭과 파일 선택 버튼을 모두 제공한다.
- 지원 확장자와 최대 크기를 미리 표시한다.
- 파일명, 오류, 업로드 중, 완료 상태를 제공한다.
- 잘못된 파일을 선택했을 때 다시 선택할 수 있어야 한다.
- 모바일에서는 드래그 기능 없이도 전체 기능을 사용할 수 있어야 한다.

## 10. 키보드·포커스·접근성

- 모든 버튼과 링크를 Tab으로 이동할 수 있어야 한다.
- 포커스 표시를 제거하지 않는다.
- DOM 순서와 시각적 순서를 일치시킨다.
- Toggle은 `role="switch"`, 현재 값은 `aria-checked`로 제공한다.
- 현재 페이지는 `aria-current="page"`로 제공한다.
- 상태 변경은 `role="status"` 또는 `aria-live`를 사용한다.

```css
:focus-visible {
  outline: 3px solid var(--color-focus-ring);
  outline-offset: 2px;
}
```

### 키보드 검증 순서

1. 새로고침 후 마우스를 사용하지 않는다.
2. Tab으로 메뉴와 입력 요소를 순서대로 이동한다.
3. Enter·Space로 버튼, 링크, Toggle을 실행한다.
4. ESC로 모달을 닫는다.
5. 포커스가 사라지거나 화면 밖으로 이동하지 않는지 확인한다.

## 11. 모션 최적화

- 상태 전환은 150~250ms 범위를 기본으로 사용한다.
- Layout Shift가 생기는 큰 위치 이동은 피한다.
- 로딩 애니메이션이 콘텐츠 읽기를 방해하지 않게 한다.
- 모션 감소 설정을 지원한다.

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    scroll-behavior: auto !important;
    animation: none !important;
    transition: none !important;
  }
}
```

## 12. 차트·데이터 표현

- 색상만으로 카테고리를 구분하지 않는다.
- 월, 카테고리, 금액을 텍스트로도 제공한다.
- 현재 월은 색상과 글자 굵기를 함께 사용한다.
- Tooltip은 마우스뿐 아니라 키보드와 터치에서도 열려야 한다.
- 모바일에서 그래프가 너무 좁아지면 가로 스크롤 또는 요약 목록을 제공한다.
- 스크린리더 사용자를 위한 차트 요약 문장을 제공한다.

```tsx
<p className={styles.srOnly}>
  1월 1,850,000원, 2월 2,200,000원, 3월 2,000,000원
</p>
```

## 15. 완료 기준

- [ ] 모든 주요 화면을 Desktop·Tablet·Mobile에서 확인했다.

- [ ] 모바일이 데스크톱의 단순 축소 형태가 아니다.

- [ ] 데이터 화면에 Empty 상태가 있다.
